# Orbit CLI: Testing Strategy & Agent Verification Contracts

**Document Version:** 1.0.0  
**Target Audience:** Orbit CLI Contributors, Core Maintainers, and Autonomous AI Coding Agents (Cursor, Antigravity, Claude Code)  
**Applies to:** `orbit/orbit-cli` (`orbit` and `orbit-server`)

---

## 1. Philosophy: Rejection of the Vanity Metric Fallacy

### 1.1 The Vanity Metric Fallacy
Targeting arbitrary 100% line or statement test coverage on a developer CLI produces diminishing engineering returns, harmful coupling, and false confidence:

1. **Brittle UI & Terminal Coupling:** Testing terminal column wrapping, ANSI color sequences, box borders, and table margins creates brittle test suites. A real-world example in the legacy testbed was `03_invite.sh` failing because LipGloss truncated `charlie@example.com` to `charlie@example.c…` to fit terminal display width.
2. **False Sense of Security:** High line coverage does not ensure resilience against catastrophic failures. For instance, `assets.Pull` had test coverage while still buffering entire multi-gigabyte payloads in memory via `io.ReadAll`, presenting silent out-of-memory risks on large assets.
3. **Agent Token & Compute Exhaustion:** In an AI-assisted workspace (Cursor, Antigravity, Claude Code), running heavyweight end-to-end multi-minute test suites for minor localized fixes wastes engineering time, context tokens, and compute budget.

### 1.2 Our Testing Approach
Orbit CLI replaces blanket percentage coverage with a **Tiered Criticality Matrix** and an **Agent Testing Contract**:
- **Zero-tolerance automated gates** for **Tier 1 (System-Critical)** invariants (security, vault permissions, non-destructive git operations).
- **Machine-readable regression contracts** for **Tier 2 (Functional Workflows)** using `--format json` instead of fragile table regex.
- **Decoupling of Tier 3 (UX & Visual Presentation)** from hard assertion gates.
- **Sub-10-second verification recipes** mapped to modified subsystem paths for fast agent feedback loops.

## 2. Tiered Criticality Matrix

| Tier | Classification | Scope & Subsystems | Verification Requirement | CI Gating |
| :--- | :--- | :--- | :--- | :--- |
| **Tier 1 (P0)** | **System-Critical Invariants** | Auth/HMAC, file permissions (`0600`), 3-strike grant burns, git non-destructive guarantees, secret masking | 100% hermetic unit & integration tests with exact invariant assertions | **Blocking**: PRs fail if any Tier 1 assertion fails |
| **Tier 2 (P1)** | **Functional Core Workflows** | Command lifecycles (`admin`, `staff`, `invite`, `port`, `env`), port allocation math, schema validation | Fast regression tests asserting on exit codes and `--format json` payload keys | **Blocking**: Gated on JSON contracts; no stdout text regex |
| **Tier 3 (P2)** | **Human UX & Aesthetics** | LipGloss tables, ASCII spinners, box borders, ANSI colors, autogenerated `--help` markdown | Sanity snapshots & visual checks only | **Non-blocking**: Excluded from strict assertion gates |

### 2.1 Tier 1 (P0): System-Critical Invariant Contracts

Tier 1 invariants represent non-negotiable security, integrity, and safety properties of Orbit. Any PR or agent modification that weakens or breaks these invariants is strictly rejected:

#### 1. Vault & Credentials Permissions
- Sensitive configuration files (`~/.config/orbit/owner.json`, `r2.env`, generated `.env`, and `config.yaml`) **must always be created with file mode `0600`** (read/write by owner only).
- Permissions must be actively validated before executing privileged owner or staff commands. If permissions are looser than `0600`, execution must abort with a security error.

#### 2. Staff HMAC & Reserved UID Protection
- Every staff HTTP request must sign payloads with HMAC-SHA256 (`X-Orbit-Timestamp`, `X-Orbit-Signature`).
- Mismatched, expired, or missing HMAC signatures must return HTTP 401 Unauthorized.
- Reserved directory accounts (`admin`, `authelia-bind`, `verdaccio-bind`, `verdaccio-ci`) must be rejected on creation, modification, or deletion.

#### 3. Admin Grant 3-Strike Lockout
- 8-digit CSPRNG grant codes permit a maximum of 3 failed attempts.
- On the 3rd failed attempt, the grant token is permanently incinerated in SQLite and cannot be redeemed even if the correct code is supplied subsequently.

#### 4. Git Workspace Non-Destructive Invariants
- `orbit repair` and `orbit sync` must **never overwrite, discard, or delete untracked or uncommitted working files**.
- Destructive commands like `git checkout -f` or `git reset --hard` are strictly forbidden in orchestrator routines.
- Repositories with uncommitted changes or diverged branches must be safely skipped during `sync`.
- `orbit repair` must only reattach `.git` metadata onto gitless trees without mutating working tree files.

#### 5. Secret Redaction
- `orbit config show` must mask all keys containing `pass`, `secret`, `token`, `key`, or `auth` with asterisks (`********`).
- Plaintext access is only permitted via explicit `orbit config get <key> --raw`.

### 2.2 Tier 2 (P1): Functional Core Workflows

Tier 2 covers deterministic business logic, state transitions, and core developer workflows:
- Command lifecycles (`admin`, `staff`, `invite`, `doctor`, `port`, `env`, `assets`, `workspace`).
- ADR-006 50-port allocation math and slot exhaustion handling.
- `.env.schema.yaml` contract parsing, validation, and generation.
- Machine-readable JSON output validity (`--format json`).

---

### 2.3 Tier 3 (P2): Human UX & Aesthetics

Tier 3 encompasses user-facing terminal formatting:
- LipGloss styled headers, key-value tables, and status badges.
- ASCII spinners, progress bars, and ANSI terminal color codes.
- Autogenerated Cobra documentation and man pages (`orbit doc`).

**Rule:** Tier 3 visual presentation must never be bound to hard assertion gates in automated test suites. Terminal width changes, padding adjustments, or styling updates must never break CI tests.

## 3. The Agent Testing Contract

AI coding agents (Cursor, Antigravity, Claude Code) and human contributors must adhere to the following rules when developing or testing Orbit CLI features:

### 3.1 The Machine-Readable Output Rule

1. **Always assert on `--format json` or `--json`:** When testing CLI subcommands, invoke the command with `--format json` (or `--json`) and assert on JSON keys using structured parsers (`jq` in bash, `json.Unmarshal` in Go).
2. **Never assert on stdout table formatting:** Never write regular expressions or substring checks against standard stdout table formatting, column widths, box borders, or ANSI color sequences.
3. **Missing Flag Protocol:** If a command lacks a `--json` or `--format json` flag, the agent must implement the structured JSON output flag rather than attempting to parse human-oriented tables.

#### Example: Table Assertion vs Machine-Readable Contract

```bash
# ❌ ANTI-PATTERN: Brittle stdout table assertion (breaks on terminal width truncation)
list_table=$(run_orbit invite list)
assert_contains "${list_table}" "charlie@example.com"

# ✔ RECOMMENDED: Decoupled visual presentation from machine-readable JSON contract
# 1. Non-blocking presence check for banner / UX
list_table=$(run_orbit invite list)
assert_contains "${list_table}" "Orbit Developer Invitations" "Table banner renders"

# 2. Strict contract assertion on structured JSON payload
list_json=$(run_orbit invite list --format json)
assert_json_field "${list_json}" ".[0].email" "charlie@example.com" "Email matches in JSON payload"
assert_json_field "${list_json}" ".[0].scope" "core" "Scope matches in JSON payload"
assert_json_field "${list_json}" ".[0].revoked" "false" "Revoked flag is false"
```

### 3.2 Subsystem Verification Recipes (<10s Execution)

Agents must run the narrowest sufficient recipe matching the modified subsystem rather than invoking long full-suite test runs:

| Touched Subsystem | File Patterns | Agent Verification Command | Target Duration |
| :--- | :--- | :--- | :--- |
| **Admin Vault** | `pkg/owner/**`, `cmd/orbit/admin*` | `go test -v ./pkg/owner/... ./cmd/orbit -run TestAdmin` | < 3s |
| **Staff IAM** | `pkg/client/**`, `pkg/staffhmac/**`, `cmd/orbit/staff*` | `go test -v ./pkg/staffhmac/... ./cmd/orbit -run TestStaff` | < 3s |
| **Invitations** | `pkg/invite/**`, `cmd/orbit/invite*` | `go test -v ./pkg/invite/... ./cmd/orbit -run TestInvite` | < 2s |
| **Workspace Git** | `pkg/orchestrator/**`, `cmd/orbit/sync*`, `cmd/orbit/repair*`, `cmd/orbit/status*` | `go test -v ./pkg/orchestrator/...` | < 4s |
| **Port Allocator**| `pkg/ports/**`, `cmd/orbit/port*` | `go test -v ./pkg/ports/...` | < 1s |
| **Environment** | `pkg/env/**`, `cmd/orbit/env*` | `go test -v ./pkg/env/...` | < 1s |
| **Assets Sync** | `pkg/assets/**`, `cmd/orbit/assets*` | `go test -v ./pkg/assets/...` | < 2s |
| **Full Regression**| Any cross-cutting changes | `go test ./cmd/orbit -run TestScenariosIntegration` | ~30s |

---

### 3.3 Test Isolation & Environment Discipline

1. **Hermetic Sandboxes:** Every test must run in an isolated sandbox. In Go tests, use `t.TempDir()`. In bash scenario tests, use `setup_test_sandbox` and `cleanup_test_sandbox`.
2. **Environment Variable Overrides:** Never touch user home directory files (`~/.config/orbit/`). Always override configuration paths with test-scoped variables:
   - `ORBIT_CONFIG_DIR`: points to temporary config sandbox.
   - `ORBIT_WORKSPACE`: points to temporary workspace root.
   - `ORBIT_API_URL`: points to local mock server.
3. **No Environmental Residue:** Tests must clean up all temporary sockets, files, and background mock servers upon completion or failure traps (`trap cleanup EXIT`).

---

### 3.4 Failure Resolution Principles

1. **Decouple Presentation from Data:** If a test fails due to formatting, column truncation, or word-wrapping, **do not modify application presentation logic to satisfy the test**. Update the test assertion to query structured JSON output (`--format json`).
2. **Preserve Invariants:** Never bypass security checks, permissions validations, or non-destructive git safeguards to make a test pass.
3. **Evidence Before Assertions:** Always inspect exact command output and exit codes before declaring a test fix complete.

## 4. Scenario Testbed & End-to-End Testing

Orbit CLI provides a complete multi-scenario testbed in `test/scenarios/` covering 10 end-to-end integration suites:

```bash
# Fast local execution of all 10 scenario suites
./scripts/test-orbit-scenarios.sh --local

# Go integration test harness running scenario suites
go test -v ./cmd/orbit -run TestScenariosIntegration

# Full containerized run simulating hermetic clean-room environment
./scripts/test-orbit-scenarios.sh --container
```

| Suite | Description | Key Invariants Tested |
| :--- | :--- | :--- |
| `01_admin.sh` | Platform Ownership & Vault | `owner.json` sealed at `0600`, OTP challenge verification, 3-strike lockout |
| `02_staff.sh` | Staff IAM Directory Client | HMAC-SHA256 request headers, reserved account protection, lifecycle actions |
| `03_invite.sh` | Developer Invitations | Cryptographic invite tokens, JSON listing contracts, revocation |
| `04_onboard.sh` | Workstation Onboarding Wizard | Token validation, checkpoint persistence and reset |
| `05_doctor.sh` | Diagnostics & Auto-Healing | Toolchain checks, disk space checks, automated remediation |
| `06_assets.sh` | Gitignored Assets (R2) | Manifest integrity, streaming uploads, credential failure handling |
| `07_ports.sh` | 50-Port Allocation (ADR-006) | Deterministic and dynamic block allocations, exhaustion handling |

| `09_config.sh` | Configuration Hardening | `config.yaml` mode `0600`, sensitive secret masking (`********`), raw access |
